1. System Topology: Servers, Services & AI Models

DocuChat AI operates as a unified, enterprise-grade multi-tier architecture consisting of 8 distinct server processes and services and 4 machine learning models working in complete orchestration.

1.1 The 8 Servers & Services in Execution

Server / Service Port Technology / Image Host / URL Primary Role & Operational Lifecycle
1. Frontend Web App 3000 React 18 SPA (Vite / Dev / Nginx) http://localhost:3000 Interactive user interface, file drag-and-drop zone, SSE stream consumer, bidirectional WebSocket chat client, and PDF.js canvas bounding box highlighter.
2. Backend API Gateway 5000 FastAPI / Uvicorn (Python 3.11+) http://localhost:5000 Core API gateway. Handles multi-tenant JWT auth, document ingress staging, query routing, SSE token streaming, safe tool execution, and database sessions.
3. Background Ingestion Worker Internal Python Worker (backend.workers.ingest_worker) Container / Subprocess Decoupled asynchronous worker. Consumes jobs from Redis / task queue, runs Docling extraction, structure chunking, embeddings generation, and vector indexing without blocking the API.
4. Docling Layout Engine 5001 quay.io/docling-project/docling-serve http://localhost:5001 IBM Docling layout vision container. Extracts headings, tables, reading order, and exact PDF bounding box coordinates (x0, y0, x1, y1). Has PyMuPDF fallback.
5. Local LLM Service 11434 Ollama Runtime http://localhost:11434 Locally hosted LLM runtime. Serves qwen2.5:3b / qwen2.5:7b for conversational answering, query expansion, and optional Nomic dense embeddings.
6. Vector Database 6333 / 6334 Qdrant Vector DB Engine http://localhost:6333 Stores dense vector chunks with Cosine distance indexing. Performs sub-millisecond Approximate Nearest Neighbor (ANN) vector search with HNSW graphs.
7. Relational Database 5432 PostgreSQL 16 Alpine / SQLite fallback postgres:5432 / rag_app.db Persists multi-tenant users, sessions, documents, ingestion jobs, chat conversations, and full message histories with SQLAlchemy async session pooling.
8. Redis Broker & Cache 6379 Redis 7 Alpine redis://localhost:6379/0 In-memory broker for the ingestion job queue (docuchat_ingest_queue) and pub/sub message broadcaster for real-time WebSocket progress updates.
Dual Database & Hybrid Storage Strategy: DocuChat AI connects by default to PostgreSQL 16 via asyncpg. If PostgreSQL is offline or running locally without Docker, it seamlessly falls back to local SQLite (backend/data/rag_app.db) via aiosqlite with zero configuration change. Qdrant similarly supports embedded local disk storage in backend/data/qdrant_storage.

1.2 The 4 Machine Learning Models in the Pipeline

Model Name Architecture Parameters / Dim Serving Engine Execution Stage & Specific Responsibility
Qwen 2.5 (qwen2.5:3b / 7b) Decoder-Only Transformer 3.09B / 7.61B params Ollama (Port 11434) Reasoning, Rewriting & Generation: Resolves conversational pronouns, generates search query expansions, evaluates agentic tools, and streams grounded answers with citations.
Nomic Embed / BGE-Small Encoder Transformer 768d / 384d normalized Ollama / FastEmbed ONNX Dense Semantic Vectorization: Converts chunks and queries into dense vectors. Default is nomic-embed-text:v1.5 (768d) or BAAI/bge-small-en-v1.5 (384d).

3. Step-by-Step Order: When You Upload a Document

When a document is uploaded, DocuChat AI executes an 11-step asynchronous ingestion workflow designed for non-blocking UI responsiveness, structural layout preservation, and precise provenance tracking.

1
Frontend Selection & Multipart HTTP Dispatch
frontend/src/App.jsx Port 3000 -> 5000

What Happens: The user drops or selects a document file in the React UI dropzone. handleFileUpload(file) validates the file size, builds a FormData multipart body containing file and optional authentication token, and sends an asynchronous POST http://localhost:5000/api/documents.

Calling Server: React Frontend on Port 3000 • Receiving Server: FastAPI on Port 5000 • Active Code: App.jsx: lines 450–510, services/api.js.

2
FastAPI Upload Validation, Multi-Tenant Auth & Disk Staging
backend/api/documents.py FastAPI backend/api/auth.py

What Happens: The endpoint upload_document() receives the upload. It parses the optional Authorization: Bearer <token> to extract user_id. It verifies the extension against ALLOWED_EXTENSIONS (.pdf, .docx, .pptx, .xlsx, .txt, .html, .png, .jpg, .jpeg), generates a UUID (doc_id = str(uuid.uuid4())), and streams the file to disk at backend/data/uploads/{doc_id}_{filename}.

Disk Location: backend/data/uploads/ • Active Code: documents.py: lines 85–120.

3
Relational DB Row & Ingest Job Record Creation
PostgreSQL / SQLite backend/db/models.py IngestJobModel

What Happens: Two database records are committed in the relational database: 1. DocumentModel(id=doc_id, user_id=user_id, filename=filename, status="queued"), and 2. IngestJobModel(id=job_id, document_id=doc_id, status="queued", progress=5). This ensures persistent job tracking across container restarts.

Database Records: DocumentModel & IngestJobModel • Active Code: documents.py, workers/job_queue.py: lines 30–45.

4
Asynchronous Job Enqueuing & WebSocket Subscription
Redis Queue / Task Pool backend/workers/job_queue.py WebSocket /ws/documents

What Happens: enqueue_document_ingestion() pushes the job payload onto Redis list docuchat_ingest_queue. If Redis is unconfigured or offline, it launches an asynchronous task pool worker. FastAPI immediately returns HTTP 200 with document metadata. The React client immediately opens a live WebSocket connection to /ws/documents/{doc_id}/progress to stream real-time percentage updates.

Protocol: Redis RPUSH & WebSocket • Active Code: job_queue.py: lines 45–65, api/websockets.py: lines 180–260.

5
Format Normalization to Visual PDF
backend/parsers/converter.py Worker Process

What Happens: The background worker executes convert_to_pdf(input_path, settings.CONVERTED_DIR). If the file is already a PDF, it validates page headers via PyMuPDF (fitz.open()). If it is DOCX, PPTX, XLSX, or TXT, it converts it to PDF using headless LibreOffice. If it is an image (PNG, JPG), PyMuPDF builds a PDF page wrapper so the frontend PDF.js canvas can display it identically. Worker broadcasts progress: 15%.

Output: A normalized PDF file path at backend/data/converted/ • Active Code: converter.py: lines 9–83.

6
Docling Microservice Extraction & Structure Parsing
Port 5000 -> 5001 Docling / TableFormer backend/parsers/docling_parser.py

What Happens: Worker calls docling_parser.parse_file(), making an HTTP POST http://localhost:5001/v1/convert/file to the Docling-serve container. Docling executes its deep vision layout model to detect headings, paragraph flows, and tabular cells with exact coordinates: {"l": left, "t": top, "r": right, "b": bottom, "page_no": page}.
Built-in Fault Tolerance: If Docling is offline, DoclingParser catches the error and executes its native pymupdf fallback, extracting blocks and word-level rects with 100% uptime. Worker broadcasts progress: 40%.

Output: List[ParsedElement] with text, heading paths, page numbers, and bounding boxes • Active Code: docling_parser.py: lines 45–130.

7
Structure-Aware Token Chunking & Provenance Retention
backend/chunking/structure_chunker.py In-Process

What Happens: structure_chunker.chunk_elements() iterates over ParsedElement objects. It groups elements respecting markdown section boundaries (# Title > ## Section) and table structures until reaching the configured token target (CHUNK_TARGET_TOKENS = 400, max 450, overlap 50). Crucially, it aggregates element bounding boxes and attaches the exact phrase text to each bounding box. Worker broadcasts progress: 65%.

Output: List[Chunk] with chunk ID, unified markdown text, page, bboxes, and section metadata • Active Code: structure_chunker.py: lines 35–140.

8
Dense Vector Embedding Generation (AI Model)
Nomic 768d / BGE 384d backend/embeddings/embedder.py

What Happens: embedder.embed_texts(chunk_texts) is called. If configured for Nomic (default), it invokes Ollama’s /api/embed endpoint to produce 768-dimensional normalized vectors. If configured for BGE, it loads BAAI/bge-small-en-v1.5 via FastEmbed ONNX runtime locally for sub-second CPU batch embedding (384 dimensions). Worker broadcasts progress: 80%.

Output: Normalized floating-point vector arrays (dim = 768 or 384) • Active Code: embedder.py: lines 35–80.

9
Vector Storage Upsert & Collection Indexing
Port 6333 (Qdrant) backend/retrieval/vector_store.py

What Happens: vector_store.upsert_chunks() sends the batch of chunk vectors to Qdrant collection doc_chunks. Every point stores: vector, ID, and payload (doc_id, chunk_id, page, text, bboxes, heading_path). Qdrant indexes points into an in-memory HNSW graph for fast Cosine similarity retrieval. Worker broadcasts progress: 90%.

Target DB: Qdrant Vector DB on Port 6333 • Active Code: vector_store.py: lines 65–110.

10
BM25Plus Lexical Inverted Indexing
backend/retrieval/bm25.py Disk: data/bm25

What Happens: bm25_index.build_index_for_document(doc_id, chunks) tokenizes chunks into stemmed lowercase n-grams, computes inverse document frequencies (IDF), and serializes the index to disk at backend/data/bm25/{doc_id}.json. Using the BM25Plus algorithm prevents score clipping on long passages. Worker broadcasts progress: 95%.

Disk File: backend/data/bm25/{doc_id}.json • Active Code: bm25.py: lines 45–120.

11
Relational DB Finalization & Real-Time WebSocket Completion
PostgreSQL / SQLite WebSocket Event backend/workers/ingest_worker.py

What Happens: Worker updates DocumentModel(id=doc_id, status="ready", chunk_count=len(chunks), page_count=pages) and sets IngestJobModel(status="completed", progress=100). It publishes the final completion event over Redis pub/sub and local WebSocket channels. The React client displays the document as ready, switches the badge to green, and mounts the document into the PDF canvas viewer.

Active Code: ingest_worker.py: lines 140–190, App.jsx: lines 510–560.

4. Step-by-Step Order: When You Ask a Question / Chat

When a user types a prompt and presses Enter, DocuChat AI executes an 11-step inference, hybrid retrieval, and grounded generation pipeline with strict provenance guarantees.

1
User Message Input & SSE / WebSocket Dispatch
frontend/src/components/Chat/ChatInput.jsx Port 3000 -> 5000 SSE / WS

What Happens: The user submits a prompt. The frontend checks connection preferences: it either sends an HTTP POST /api/chat expecting a Server-Sent Events (SSE) stream or dispatches a JSON packet over the existing /ws/chat WebSocket channel containing: {message, conversation_id, active_doc_ids}.

Active Code: ChatInput.jsx, services/api.js, services/websocket.js.

2
Multi-Tenant Session Validation & Context Window Assembly
PostgreSQL / SQLite backend/api/chat.py backend/api/websockets.py

What Happens: Backend validates JWT bearer token to verify user ownership. It looks up or creates the ConversationModel, saves the user message as a new MessageModel(role="user", content=message), and queries the database for the last 6 conversation turns to maintain conversational continuity.

Active Code: chat.py: lines 35–75, websockets.py: lines 60–110.

3
Agentic Tool Intent Evaluation
Agentic Tools backend/tools/registry.py backend/llm/router.py

What Happens: Before performing full document retrieval, the system evaluates if the prompt requires a vetted tool: 1. Arithmetic or calculations → calculator (safe AST parser, zero eval), 2. Tabular generation requests (e.g. “export as Excel sheet”) → export_excel (OpenPyXL generator), 3. Real-time market, movie, or weather queries → web_search. If a standalone tool matches, it executes safely within sandbox limits.

Active Code: registry.py: lines 50–90, tools.py: lines 20–40.

4
Intent Routing: Document Mode vs ChatGPT Real-World Mode
backend/llm/router.py In-Process

What Happens: query_router.route_query() inspects the active document scope and question text: 1. If no documents exist or active_doc_ids is empty → routes to "general" mode (ChatGPT real-world mode), 2. If documents are active and query is a conversational greeting (e.g., “hello”, “who are you”) → routes to "general", 3. If documents are active and query asks for facts → routes to "document" mode to enforce strict document grounding.

Output: (route_type, badge_label) • Active Code: router.py: lines 15–44.

5
Multi-Query Rewriting & Pronoun Disambiguation (Server Call & AI Model)
Qwen 2.5 (11434) backend/llm/rewriter.py

What Happens: If in "document" mode, query_rewriter.transform_query() analyzes the question and chat history. It prompts Ollama to resolve ambiguous references (e.g., converting “What were its results?” to “What were the BLEU score results of Transformer base model?”). It also triggers specialized rule expansions for tables, summaries, and financial reports, returning 3 search variants: [standalone_query, alt_1, alt_2].

Active Code: rewriter.py: lines 20–95.

6
Parallel Hybrid Retrieval: Dense Vectors (Qdrant) + Sparse Lexical (BM25Plus)
Qdrant Port 6333 backend/retrieval/pipeline.py Disk: data/bm25

What Happens: retrieval_pipeline.retrieve() executes parallel async retrieval for each generated query variant: 1. Dense Vector Search: Embeds query via embedder.embed_query() and searches Qdrant (Top 30 by Cosine distance), 2. Sparse Lexical Search: Evaluates query against the BM25Plus index on disk (Top 30 by keyword frequency). This guarantees exact term matching (e.g. acronyms, IDs, dates) and semantic matching.

Output: Parallel ranking lists from Qdrant and BM25Plus • Active Code: pipeline.py: lines 40–65.

7
Reciprocal Rank Fusion (RRF) & Semantic Deduplication
backend/retrieval/fusion.py backend/retrieval/dedup.py

What Happens: Candidate lists are combined using Reciprocal Rank Fusion: $RRF(d) = \sum \frac{1}{60 + rank(d)}$. This unifies dissimilar vector and BM25 scoring scales into a single fair ranking. Then, deduplicate_chunks() calculates Jaccard word similarity and character 3-gram overlap, removing redundant or overlapping text chunks with similarity $> 0.88$.

Active Code: fusion.py: lines 12–55, dedup.py: lines 10–45.

8
Cross-Encoder Deep Reranking & Max-Scaling Normalization (AI Model)
BAAI/bge-reranker-base backend/retrieval/reranker.py

What Happens: The top 40 candidate chunks are passed to reranker.rerank(). BAAI/bge-reranker-base evaluates the combined pair [Query, Chunk Text] using full cross-attention. It applies Max-Scaling Normalization (raw / max_s) so that secondary relevant passages are not artificially suppressed by sigmoid flattening. Passages below SCORE_THRESHOLD = 0.25 are dropped. The top 3–5 highest-ranking passages are selected.

Active Code: reranker.py: lines 25–75.

9
Grounded Prompt Assembly, LangChain Orchestration & Token Streaming (AI Model)
Qwen 2.5 (11434) backend/llm/generator.py backend/llm/langchain_adapter.py

What Happens: grounded_generator formats the retrieved passages into numbered context blocks [1] (Page P): text with strict anti-hallucination system directives. It invokes Ollama (qwen2.5:3b / 7b) via native streaming or the LangChain ChatOllama adapter. Tokens stream character-by-character to the client UI as SSE events (event: token) or WebSocket messages.

Active Code: generator.py: lines 20–110, langchain_adapter.py: lines 70–160.

10
Real-Time Live Web Knowledge Fallback
backend/retrieval/web_search.py Yahoo / DDG / Wiki

What Happens: If the model concludes that the document lacks the requested answer (e.g. “This is not mentioned in the document”) or if routed in general ChatGPT mode, the system seamlessly queries live_web_search. It hits Yahoo Finance API for real-time tickers, DuckDuckGo Lite for current news/movies, and Wikipedia REST API for sports/facts with zero API key dependencies.

Active Code: web_search.py: lines 25–190.

11
Global Best-Box Refinement & Synchronized Canvas Highlighting
backend/llm/generator.py frontend/src/components/PdfViewer/PdfViewerDrawer.jsx

What Happens: Once generation completes, refine_citations_for_answer() performs global n-gram intersection scoring between generated answer tokens and chunk bounding box text. It isolates the single winning bounding box containing the answer, preventing the legacy “blue screen” multi-box clutter bug. The citation event transmits {page, bboxes: [winning_box]} to the React viewer, triggering a high-contrast pulsing glow on the PDF.js HTML5 canvas.

Active Code: generator.py: lines 135–220, PdfViewerDrawer.jsx.

Enterprise user authentication and session management. Implements Argon2id password hashing with PBKDF2-HMAC-SHA256 fallback, signed JWT bearer tokens with 24-hour expiration, Role-Based Access Control (RBAC: admin/user), and default seeded demo accounts.

backend/api/websockets.py Production WebSockets

5.4 Embedding & Vector Storage Layer

backend/embeddings/embedder.py Embedding Service
Unified embedding service supporting dual backends: Nomic Embed (768d via Ollama) and BGE-Small (384d via FastEmbed ONNX runtime / SentenceTransformers). Formats query search instructions and normalizes vectors.

backend/retrieval/vector_store.py Qdrant Client
Manages Qdrant Vector DB connection (Port 6333) with embedded storage fallback. Creates collection doc_chunks with Cosine distance, handles batch upserts with chunk metadata, and executes document-filtered ANN vector searches.

5.5 Retrieval, Fusion, Deduplication & Live Web Layer

backend/retrieval/bm25.py Lexical BM25Plus Index
Implements BM25Plus sparse lexical retrieval. Persists per-document inverted indexes to disk at backend/data/bm25/{doc_id}.json. Solves the standard BM25 negative score bug on long passages.
• Called By: ingest_worker.py, pipeline.py • Calls: rank_bm25, config.py
backend/retrieval/fusion.py Hybrid Rank Fusion
Merges disparate ranked lists from vector ANN search and BM25Plus using Reciprocal Rank Fusion ($k=60$) and score-weighted fusion. Normalizes candidate scores into a unified distribution.
• Called By: pipeline.py • Calls: None (Pure math)
backend/retrieval/dedup.py Semantic Deduplicator
Filters redundant chunks by chunk ID, Jaccard word set similarity, and character n-gram overlap ($> 0.88$). Eliminates duplicate headers and sliding-window chunk overlaps.
